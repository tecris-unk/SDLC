# Дополнительные спецификации веб-приложения «TourGuide»

## 1. Бизнес-правила формирования маршрутов
- **BR-01 (Ограничение размерности маршрута):** один экскурсионный маршрут должен содержать от 2 до 15 точек посещения для сохранения комфортной продолжительности пешей экскурсии и соблюдения времени расчёта.
- **BR-02 (Отказоустойчивость геомаршрутизации):** при недоступности внешнего геосервиса OpenStreetMap (OSRM) или превышении лимита ожидания `1500 мс` сервер ASP.NET Core автоматически выполняет резервный расчёт расстояний по сферической формуле гаверсинусов с городским коэффициентом удлинения пути `1.3`.
- **BR-03 (Резервный режим АИ-агента):** при недоступности внешнего LLM API система формирует подборку достопримечательностей на основе фильтрации объектов с наивысшим рейтингом в запрошенной категории.

## 2. Нефункциональные требования (FURPS+)
- **Производительность (`REQ-PERF-001`):** время отклика REST API при построении и оптимизации маршрута до 15 точек и при загрузке каталога не должно превышать `2.0 с`.
- **Безопасность (`REQ-SEC-001`):** аутентификация выполняется по стандарту Bearer JWT в ASP.NET Core Identity; пароли пользователей хранятся в БД PostgreSQL исключительно в виде криптографических хешей (PBKDF2 / BCrypt).
- **Портируемость (`REQ-PORT-001`):** серверное приложение (.NET 8), клиентский интерфейс (React + Nginx) и СУБД PostgreSQL упаковываются в изолированные Docker-контейнеры и запускаются через `docker-compose`.
