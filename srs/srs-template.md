# Спецификация требований к программному обеспечению (SRS)

## 1. Введение {#1-introduction}

### 1.1 Назначение {#11-purpose}
Настоящий документ представляет собой спецификацию требований к программному обеспечению (Software Requirements Specification, SRS) для веб-приложения **«TourGuide»** — путеводителя по достопримечательностям с интерактивной картой, конструктором маршрутов экскурсий и интеллектуальным агентом рекомендаций, разрабатываемого на платформе **C# (ASP.NET Core)**.

### 1.2 Область применения {#12-scope}
Система «TourGuide» позволяет туристам, экскурсоводам и местным жителям просматривать каталог интересных мест, фильтровать их по категориям, длительности посещения и рейтингу, собирать экскурсионные маршруты, получать персонализированные подборки локаций с помощью АИ-агента и отображать объекты на интерактивной карте.

## 2. Обзор продукта {#2-product-overview}

### 2.1 Перспектива продукта {#21-product-perspective}
«TourGuide» - новый самостоятельный программный продукт на платформе C# (ASP.NET Core). Ранее туристам, гидам и местным жителям приходилось пользоваться несколькими инструментами одновременно: сайтами-путеводителями для описания мест, картами для навигации и заметками/мессенджерами для сборки маршрута. Информация о достопримечательностях разрознена, а переход между сервисами во время экскурсии неудобен. Приложение должно объединить каталог достопримечательностей, построение экскурсионных маршрутов и интерактивную карту в одном веб-интерфейсе.

**Внешние системы и зависимости:**
- **Картографический сервис** (OpenStreetMap + Leaflet и/или Яндекс.Карты API) - для отображения карты, маркеров достопримечательностей и линии экскурсионного маршрута.
- **Сервис ИИ-рекомендаций (LLM API)** - для обработки текстовых запросов пользователя в свободной форме и подбора релевантных точек из каталога с учётом радиуса и времени.
- **SMTP-сервер** (опционально на этапе MVP+) - для отправки уведомлений и путевых листов экскурсий (например, подтверждение регистрации).

### 2.2 Функции продукта {#22-product-functions}
- Каталог достопримечательностей с описанием, фотогалереей, категориями, рейтингом и режимом работы.
- Поиск и фильтрация объектов по району, категории, длительности осмотра и минимальному рейтингу.
- Построение и сохранение экскурсионных маршрутов (в рамках MVP — ручной набор и упорядочивание точек пользователем).
- Интерактивная карта с маркерами достопримечательностей и визуализацией выбранного маршрута.
- Личный кабинет пользователя (избранные места и сохранённые маршруты).
- Интеллектуальный АИ-агент для подбора достопримечательностей по запросу в свободной форме с учётом заданного километража и тематики.

### 2.3 Технологический стек и ограничения {#23-constraints}
- **Backend**: язык программирования C# (.NET 8), фреймворк ASP.NET Core Web API (веб-платформа), ORM Entity Framework Core.
- **Frontend**: библиотека **React** (SPA) для адаптивного веб-интерфейса.
- **СУБД**: **PostgreSQL**.
- **Инфраструктура**: контейнеризация **Docker** и `docker-compose`.

## 4. Детальные требования и приоритизация {#4-specific-requirements}

### 4.1 Функциональные требования {#41-functional-requirements}
- **REQ-FUNC-001 (Приоритет: 10 — Must have)**: Система должна предоставлять каталог достопримечательностей и карточку места с отображением названия, краткого описания, истории, категории, рейтинга, фотографий и режима работы.
- **REQ-FUNC-002 (Приоритет: 20 — Should have)**: Система должна обеспечивать поиск достопримечательностей по названию и фильтрацию по категориям («Музеи», «Парки», «Архитектура», «Еда»), рейтингу и длительности посещения.
- **REQ-FUNC-003 (Приоритет: 20 — Should have)**: Система должна позволять пользователю добавлять выбранные достопримечательности в экскурсионный маршрут, задавать порядок обхода точек и сохранять маршрут.
- **REQ-FUNC-004 (Приоритет: 20 — Should have)**: Система должна отображать маркеры достопримечательностей и построенную линию экскурсионного маршрута на интерактивной карте с использованием OpenStreetMap / Leaflet API.
- **REQ-FUNC-005 (Приоритет: 30 — Could have)**: Система должна позволять авторизованному пользователю сохранять понравившиеся достопримечательности в «Избранное» и сохранять готовые маршруты экскурсий в личном кабинете.
- **REQ-FUNC-006 (Приоритет: 50 — Won't have for MVP)**: Система должна предоставлять административный интерфейс для управления контентом каталога достопримечательностей (отложено на пост-релизный этап; на старте база заполняется подготовленным набором данных).
- **REQ-FUNC-007 (Приоритет: 20 — Should have, добавлено во 2-м раунде)**: Система должна предоставлять АИ-агента рекомендаций, формирующего список подходящих достопримечательностей из каталога по текстовому запросу пользователя с учётом тематики и заданного километража (радиуса).

### 4.2 Нефункциональные требования {#42-non-functional-requirements}
- **REQ-PERF-001**: Время отклика API при построении экскурсионного маршрута (до 15 точек) с использованием картографического сервиса (OpenStreetMap/Leaflet) не должно превышать 2 секунд при стандартном интернет-соединении. Время загрузки главной страницы каталога также не должно превышать 2 секунд.
- **REQ-SEC-001 (Приоритет: 10 — Must have)**: Система должна обеспечивать безопасное хранение учётных данных пользователей (хеширование паролей) и аутентификацию через JWT-токены в ASP.NET Core Identity.
- **REQ-PORT-001**: Серверная часть на C# (ASP.NET Core) и база данных PostgreSQL должны разворачиваться в изолированных Docker-контейнерах на любой хост-системе.
